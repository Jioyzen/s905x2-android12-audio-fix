1. 原始 IMG 两个工作区副本 SHA 相同；以当前工作目录的原始 IMG 作为审计输入。

4. 从最终发布镜像提取全部12个运行文件，比对项目载荷SHA一致；核对空目录、mode、uid/gid与SELinux标签。
5. 对照原始与最终 libamaudioutils.so，确认 SHA 为 `4f04e88129a0bbd05b185543ad9867b518c31d80aab29f08b01f8935439b7623`，完全未修改。
6. XML 与 build.prop 保存完整文本差异，音频策略另保存语义差异。build.prop确认只有一项属性值变化。

## 既有实机验证及限制

DTS-HD／TrueHD修复过程中同时核对AudioPolicy实际请求、ALSA参数、硬件指针推进、IEC burst结构及用户实际听感／画速／同步，不仅依赖功放标识。用户最终确认多片源长seek及多轮切轨满足需求。

DTS满周期修复有独立结果：旧库对相应样本输出0字节，新库输出与FFmpeg逐字节相同；7字节碎片输入结果相同；旧AC3／DTS-ES样本新旧输出相同。实机约3秒抓到312×2048字节帧，转换字节序后FFmpeg解码为48k／6ch／5.1(side)，PCM非零，用户反馈正常。相关验收JSON与ABI／输出对照保存在 evidence/，该JSON本身是临时加载阶段快照，后续固化记录已并入本页。

系统软件解码短窗口中，DTS-HD解码线程约占一个CPU核17%，三个不同轨道约41.87／21.21／14.87秒窗口欠载增量均0；这是特定窗口证据，不能替代所有音轨的长期压力测试。软解输出是立体声PCM16，不含Atmos／DTS:X对象渲染。普通软件解码成功也不代表强制audio tunnel已覆盖。

## 将载荷合入离线镜像的方法

本项目提供文件和可核验的方法，不包含连接离线盒子的自动刷写脚本。若日后需合入其他镜像，应先核对基线、架构、空间与分区布局。

1. 保存现场完整 vendor／system／product 和 LP 元数据；基于现场副本构建，保留其他已完成的移植修改。
2. 用 `scripts/export_rootfs.py` 导出载荷与真实空目录。按 payload.json 的 inode_path 注入对应 ext4，普通文件0644、root:root，并恢复正确SELinux xattr。
3. 三个system库位于system镜像内的 `/system/...`；vendor／product镜像内部路径从 `/lib`、`/etc` 开始。APEX库按离线展开路径写入。
4. 将新增空目录及init rc一并落盘。init负责后续odm遮罩和sysfs权限；不要改写sysfs文件到镜像中，不需要删ODM原库。
5. 逐文件重新提取校验字节／SHA／标签，运行 `e2fsck -fn`，确认容量足够。镜像文件若有扩容，还需单独验证实际逻辑分区容量，不能直接追加字节后刷入较小分区。
6. 在恢复环境按现场LP解析所得线性映射写对应分区，fsync后使用直接I/O完整回读并核对SHA，再确认LP元数据未变。本文不提供历史固定偏移命令。
7. 人工重启后检查12文件、heap属性、MS12遮罩、HDMI节点权限、音频服务，以及真实起播／切轨／长seek。恢复失败时用本次现场完整分区备份回滚。

`baseline/rootfs`是原镜像中的文件级参照，不是后来整机的完整回滚包。单独恢复其中十个文件也不会自动撤销新增init、空目录或运行时挂载；回滚完整固件应使用相应时点的分区备份。

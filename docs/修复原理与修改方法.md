# 修复原理与修改方法

本文件针对 README 中的最终 12 文件方案。所有地址为该版本 ELF 的地址，不能套用于同名的其他固件。精确输入／输出 SHA 与完整字节变更以 manifests 为准；这里解释每层修改为什么存在。

## 1. 原始缺陷分布

正常压缩音频路径为：播放器 AudioTrack → AudioPolicy → Amlogic HAL → libamaudioutils 的 spdifenc 封装 → libdroidaudiospdif → ALSA → HDMI → 功放。系统软解路径则通过 MediaCodec／ACodec → OMX 包装器 → FFmpeg／swresample → PCM AudioTrack → 原 HAL。

原始镜像存在多层缺口：AudioPolicy 缺明确 HD 输出声明；HAL 将超出白名单的源格式回退 PCM；原 AOSP SPDIF 库缺少所需 HD 封装；非 MS12 HBR 路径还存在载波、呈现位置和延迟的单位错误。切轨的流归属和 HDMI 锁存、seek 的解析状态又是独立故障。因此“功放点亮”不足以证明数据吞吐、实际声音和时钟正确。

## 2. audio.primary.amlogic.so：格式、时钟、缓冲与流生命周期

### 原镜像至最终产物的结构变化

原始 SHA 为 `268ac992d716…`，大小 460260 字节；最终 SHA 为 `6b582b0c2ad3…`，464356 字节，增加 4096 字节。具体完整原始 SHA 见 payload.json。ELF 的可执行 LOAD 段由 VA 0x30a80 开始，最终扩至 0x6e000；后续可写段的文件偏移后移 0x1000，保持原虚拟地址；末段 BSS 大小也增加。故不能用同文件偏移处所有差异字节数直接当作“修改的指令数量”。前后 program headers 保存在 evidence/hal-original-elf.txt 与 hal-final-elf.txt。

基于该文件的 Thumb 分支与 RX 空间注入保留 ABI、原函数入口与返回协议；完整变更既包含指令和洞穴，也包含 ELF 头／段／节布局变更。manifests/binary-deltas.json 记录从原镜像原件到最终文件的全部字节编辑，scripts/reconstruct_binaries.py 用输入哈希、旧字节和最终哈希三重校验精确重建。

### 各项处理

| 修改点 | 实现 | 解决的问题 |
|---|---|---|
| get_sink_format 白名单 | 最初文件偏移 0x51266／0x5126a／0x51314 三处指令扩展 HD 格式范围与 AUTO 保留条件，最终载荷继承 | 原 HAL 对 DTS-HD／TrueHD 请求改为 PCM |
| IJK DTS-HD 别名 | aml_audio_set_spdif_format 的 VA 0x5b804 补丁链，把适用的 type3 升到 DTS-HD type8，stream+0xfc 写 ALSA rate=192000 | IJK 提交 DTS 格式但携带 HD 扩展时载波吞吐不足 |
| DTS-HD 物理队列 | 0x416c4 分支修改，使用 period8192／buffer32768 | 直通写入队列不足、供给不连续 |
| 呈现位置 | out_get_presentation_position 入口附近 VA 0x40806 挂钩，对相应别名 HBR 路径返回的 64 位帧位置÷16；core／原生 DTS_HD 有保护 | 音频硬件计数被当作 48k 内容帧，播放器追随错误时钟、画速不稳 |
| TrueHD 载波与物理缓冲 | type7 使用 192k；仅 TrueHD 将 period_count 改为8、start_threshold=65536 | 4K60／高码率播放时偶发欠载、功放格式闪烁 |
| TrueHD 延迟 | out_get_latency_frames 对 TrueHD 的硬件 delay 换算由÷4改为÷16 | 扩大缓冲后被夸大的上报延迟引起固定音画偏移 |
| seek／flush | 清除残留 TrueHD 格式钉定；TrueHD 经原 standby 重建编码器；其他目标压缩流重置计数基线，保留 stream+0x188 基线 | 跳转后格式残留、错位时钟、旧编码状态污染 |
| 虚拟缓冲自愈 | VA 0x5b252 的 movs r0,#2 改为 #0，继承旧修复 | 欠载后虚拟缓冲无法重初始化、生产者停写 |
| 关闭流归属保护 | 比较 active_outputs 槽中的指针，只有仍属于旧流才清空 | 旧流延后 close 把新流的活动指针抹掉 |
| TrueHD 切入建流 | 首次累计完整 MAT burst 61440 字节后，每新流只做一次原生 standby，下一 write 重建，标志在 standby 复位 | 切入显示 TrueHD 却无声，短 seek 才恢复 |
| AC3 N1 锁存 | tinyalsa 时间戳确认 RUNNING／DRAINING 后，读取现有 AUD_N1 并同值回写一次；stream+0x156 标志避免重复 | HD→AC3 时数据有效但功放停旧格式、无声 |
| DTS-ES 6.1 core | type3 且已确认 mask0x13f 路径保持普通 DTS，config.rate 使用 hal_rate；跳过 HD position 除法 | 普通 core 被错误升级 HBR |
| ExoPlayer 原生 DTS_HD | type8 且内部格式0x0c000000时明确设置192k | 原补丁只覆盖 IJK 别名，标准 DTS_HD 请求点亮却无声 |
| 满周期 DTS core | out_write_direct 锁内检查 BE core 头、48k、512样本、2048字节和紧邻下一 core；stream padding+0x157 标记，必要时一次 standby；格式入口保持type3／48k | DTS5.1(side)满码率样本错误使用 HD 载波 |

本平台 HBR 的正确组合是 ALSA 192000、spdifout clk 98.304 MHz、有效硬件指针约 768000 帧／秒。Android 内容时间轴仍通常为 48000。32768 硬件帧约42.67 ms；TrueHD 65536帧约85.33 ms。DTS-HD muxer 的 dtshd_rate=768000 是 IEC 序列化口径，不是把 ALSA hw_params 改成768k。presentation、latency、字节吞吐是不同量，不能共用一个未经验证的除数。

N1 使用现有寄存器原值，不能把某次读到的0xc0固定写到所有格式。解析前缀“[0x10003200]0x”长度为14。正式方案没有 sleep／定时FIFO复位；HDMI debug 节点权限是这项正式修复的运行依赖。现有实现依赖本 ROM 的 sysfs 接口与 permissive 前提，移植需要重新审查。

## 3. libdroidaudiospdif.so：重建封装与状态管理

原始12564字节，最终613392字节。保留 AOSP SPDIFEncoder／FrameScanner ABI 和普通 AC3、E-AC3、DTS 路径；HD 使用固定 FFmpeg n8.1.3 parser 与 spdif muxer。libamaudioutils 按固定对象大小分配，兼容类基类布局不能随意增加成员；构造符号的 GCC／Clang mangling 差异由 abi_alias.S 适配。

1. DTS core 后发现 EXSS 同步字 `64 58 20 25` 时，将完整 HD AU 交给 DTS-HD muxer。典型512源样本产生32768字节、Pc=0x0411的burst。
2. 长 seek 可能先输入孤立 EXSS；submit_frame 忽略这类扩展，等待下个完整 core＋EXSS AU，避免 muxer 失败状态污染后续帧。
3. hd_flush 关闭并重建 parser／codec／muxer，丢弃未完成 AU／MAT，使新时间轴不拼接旧状态。
4. TrueHD 使用上游 MAT 封装，典型61440字节／burst；保留标准起始、中段、结束码逻辑。
5. 对 DTS-I 的2048字节满周期core，8字节IEC头会使2056字节超周期，旧实现反复清零。按上游FFmpeg规则省略容不下的preamble，仍按16位字节交换发送完整帧；startDataBurst／flushBurstBuffer 相应跳过头和Pd，不截帧、不扩大载波周期。

DTS满周期样本曾用7字节碎片输入独立验证；新输出与FFmpeg逐字节一致，旧AC3／DTS-ES样本新旧输出一致。HAL的新分类仍限定已验证BE、48k、512样本、2048字节且同次write内看到下一core；LE／14bit／独立2048字节write等未获全覆盖保证。

## 4. audio_policy_configuration.xml：完整策略变化

原始14299字节，最终17228字节。除HD格式外，文件还继承输出结构改写，完整语义变化保存于 manifests/policy-semantic-diff.json，完整文本差异位于 patches/vendor-audio_policy_configuration.xml.diff。

- 原泛化的 direct output、tunnel direct output 改为明确的 direct raw、tunnel raw，并增加 multi pcm；HDMI route 跟随端口名称更新。
- direct raw、tunnel raw、HDMI devicePort 配套声明 DTS_HD／DOLBY_TRUEHD profiles；HDMI encodedFormats 声明 AC3、E-AC3、DTS、TrueHD、DTS-HD。
- DTS 的相应 mix／device profiles 补 AUDIO_CHANNEL_OUT_6POINT1，解决 DTS-ES 6.1 被策略拒绝。
- direct raw 的 maxOpenCount=2 允许新旧句柄短暂交接，不代表两条硬件流同时播放。
- mmap_no_irq_out 的声明存在继承性变化；原 tunnel a2dp 端口被移除，三个 BT A2DP route 移除对应source。这些是最终文件的真实差异，未单独证明每一项均为HD直通必需，也没有新增蓝牙音频全面回归承诺。
- 最终 tunnel pcm／raw、multi pcm 仍带 HW_AV_SYNC。早期移除四处 HW_AV_SYNC 的实验未成为最终文件，不能写成最终修复。
- 空白、注释和排版也有改写；不得只用文本增删行数推导功能。

## 5. OMX 包装器、两份 codecs XML 与原厂依赖

最终 vendor/lib/libstagefrighthw.so 是本项目软件 OMX 包装器，静态链接 FFmpeg6.1.1 libavcodec／libavutil／libswresample；目标为六类环绕音频，其他组件完整转发至新增 libstagefrighthw_original.so。后者等于原始镜像插件30616字节，必须保留。

组件名称为 OMX.google.ffsurround 的 ac3／eac3／dts／dtshd／dtse／truehd decoder。名字中的google遵循框架软件组件命名约定，本项目并非Google官方组件。主media_codecs.xml注册AC3／E-AC3／标准TrueHD，ext文件注册DTS家族；组件选择、实际初始化和非零PCM输出均需要验证，单加XML声明不产生解码能力。

parser处理分块输入；decoder输出经swresample把中置与环绕正确下混为交错双声道PCM16。保留源采样率，最终硬件采样率由混音路径决定。端口变化、PTS按样本推进、EOS尾部和flush重置均有处理。TrueHD每AU约40样本，48k时每秒约1200次回调；聚合约20ms后降为约50次，EOS输出剩余样本，flush丢弃旧聚合与解析状态。输入4×256KiB、输出4×64KiB是容量上限，不要求每次填满。

视频与其他OMX组件的枚举、角色、创建和销毁继续委托原插件，包装器维护自己创建组件的归属。FFmpeg已静态链接，正式根文件系统无需另加libavcodec.so、libavutil.so、libswresample.so；src下的静态库和链接stub是主机构建材料，不是Android新增运行载荷。

## 6. 三个系统库与 product 属性

libmediavendor_ext.so补标准audio/true-hd到旧audio/truehd的兼容与TrueHD coding0x7f000002、参数index0x7f100004查询分支。system与VNDK两个libstagefright_xmlparser.so分别为标准MIME补decoder／encoder角色。三库均在原二进制内局部修改，大小不变；旧诊断字符串／代码区域用于新分支，保留相邻数据和原映射。原始至最终同文件偏移差异分别为109、49、51字节，完整编辑见binary-deltas。原始补丁源位于src/decoder/patch_*，其中历史NDK路径保留作来源参考；跨目录精确复现使用scripts/reconstruct_binaries.py。

product/etc/build.prop与原始镜像比对仅一项值变化：`ro.af.client_heap_size_kbyte=2048`改为8192。ExoPlayer DTS-HD请求4194536字节共享内存，超过原2MiB client heap导致ENOMEM；8MiB解决分配问题。它不是网络缓存、整机可用RAM或ALSA时长，且不能由仅替换vendor HAL持久实现。

## 7. init／空目录／权限

新增zz-nonms12-audio.rc在post-fs-data把vendor/etc/audio-noms12-empty bind到odm/lib，使本机保持已验收的非MS12路径。ODM分区原库未删除、未改字节；整个目录同时遮住独立解码库，因此配套系统软解必须使用新插件。没有把需要的旧独立解码库偷偷复制到遮罩目录。

rc在音频HAL启动前设置HDMI debug节点root:audio／0220，并在boot_completed后再设一次，覆盖其他rc的权限回写。没有修改SELinux状态或策略；依赖设备原有permissive环境。普通文件root:root／0644、空目录0755、正确xattr均是固化要求，标签清单见payload。

## 8. 没有保留的实验与适用范围

libamaudioutils.so最终与原镜像SHA完全一致，取消首块静音memset的试验已被证伪。HBR降至48k、只扩大缓冲而不改单位、固定300ms补偿、定时FIFO复位、SDK／厂商伪装、APP注入、后台轮询均不是最终交付。9月28日DTS缓冲512→8192实验不能单独代表后续完整HBR／时钟／EXSS方案。

TCL参考机走eARC OFFLOAD、4096字节HAL缓冲，内容逻辑率48k；盒子走RAW_DIRECT及192k HBR。TCL的稳定呈现时钟可作对照，不能照搬其硬件同步接口或把盒子的载波降频。两机飞牛自动模式均曾回退PCM；本项目完成的是系统后级与兼容解码修复，应用自身门控仍应按实际版本／设置判断。
